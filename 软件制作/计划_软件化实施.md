# 软件化实施计划（草稿 v0.1）

> 创建：2026-10-28 ｜ 维护：闫 ｜ 状态：待评审
> 上级文档：`docs/软件化交付流程.md`（六步流程与成熟度评估）
> 本文只写**怎么落地**：增量拆分、文件职责、验收标准、排期、风险。

---

## 一、目标（一次说清）

把现有 20+ 脚本收敛成**一个有门面、有配置、有日志、能打包**的软件，而不是重写功能。

**达成判定（四条全过才算完成）**

1. 桌面上只有一个入口 `egomed.bat`，子命令覆盖全部日常操作；
2. 根目录 bat 从 11 个减到 ≤3 个，解释器解析逻辑 11 处 → 1 处；
3. 长任务（回归/长稳）在 GUI 日志面板里能看到实时进度；
4. 三类故障（断网 / 关服务端 / 端口占用）各有唯一错误码与一句人话解释。

---

## 二、总体思路：三个"不"

| 原则 | 含义 |
|---|---|
| **不重写** | GUI 就是 `client/live_console.py`，补齐菜单与日志面板，不新做界面框架 |
| **不动业务** | 不碰 `server/**`、不改引擎、不改契约 v1.0.3 |
| **不删旧路** | 11 个 bat 保留为转发壳，现场习惯不破坏，随时可回退 |

## 三、四个增量（每个可独立验收）

### 增量 1：统一入口（本目录 → 根目录）

**产出**：`launcher.py` + `egomed.bat` + `config.toml`

**职责划分**

| 文件 | 职责 | 不做什么 |
|---|---|---|
| `egomed.bat` | 解释器兜底、chcp、调用 launcher、透传退出码 | 不写业务逻辑 |
| `launcher.py` | 解释器探测、配置加载、子命令分派、返回码、doctor 自检 | 不实现 GUI 与推理 |
| `config.toml` | 唯一配置源 | 不存敏感信息 |

**子命令**

```
egomed.bat                    打开 GUI（默认）
egomed.bat demo               起服务端（等健康）后开 GUI
egomed.bat doctor             环境自检（文本输出）
egomed.bat diag               生成诊断包
egomed.bat console            直接开 GUI（同默认，显式写法）
egomed.bat calibrate          机位校准
egomed.bat regress [--suite]  一键回归
egomed.bat soak --minutes N   长稳测试
```

**返回码约定**

| 码 | 含义 | 错误码前缀 |
|---|---|---|
| 0 | 成功 | — |
| 1 | 用户取消 | — |
| 2 | 环境问题 | E3xxx |
| 3 | 连接问题 | E1xxx |
| 4 | 验收失败 | 回归不绿 |
| 5 | 功能未实现（骨架阶段） | — |

**验收标准**

- [ ] `launcher.py doctor` 输出 8~10 项检查，全绿时退出码 0，有 FAIL 时退出码 2；
- [ ] `launcher.py --help` 列出全部子命令；
- [ ] `egomed.bat doctor` 双击可跑通（不依赖当前工作目录）；
- [ ] 在无 `egomed` conda 环境的机器上，`egomed.bat` 给出明确提示（E3001），不是 traceback。

**风险**：中文控制台编码 → 统一用 `[OK] / [!!] / [--]` 标记，禁用 emoji；`stdout.reconfigure(encoding='utf-8')` 兜底。

### 增量 2：GUI 菜单 + 日志面板

**产出**：`client/live_console.py` 新增菜单栏（文件/运行/工具/帮助）与 ⑥ 运行日志面板

**关键设计**

- 长任务用 `subprocess.Popen` + 线程读 stdout，逐行滚进日志面板（不阻塞界面）；
- 子进程结束时把返回码翻成一句话（"回归通过" / "回归失败，见 runs/reports/…"）；
- 「关于」显示：软件版本、契约版本、Python 路径、项目根、服务端地址。

**验收标准**

- [ ] 点「环境自检」，面板实时出现每一行输出，结束时显示结论与返回码；
- [ ] 点「一键回归」，界面不卡死，可中途「停止」（terminate 子进程）；
- [ ] 「关于」里的版本号与 `VERSION` 文件一致。

**风险**：tkinter 与线程混用的界面卡顿 → 日志用队列 + `after()` 轮询，不在工作线程里直接操作控件。

---

### 增量 3：配置持久化

**产出**：`config.toml` 读写 + 设置窗口

- 记住上次的源类型、路径、fps、渲染模式、麦克风开关；
- 命令行 > 环境变量 > 配置文件 > 内置默认，四层优先级；
- 配置文件损坏时：**备份为 `.bak` + 用默认值启动 + 提示**，不阻塞启动。

**验收标准**

- [ ] 关掉重开，上次选择仍在；
- [ ] 手工写坏 `config.toml`，启动不崩，且提示已备份恢复；
- [ ] 删掉 `config.toml`，程序用默认值正常启动并重建该文件。

---

### 增量 4：错误码与诊断

**产出**：错误码表（`软件制作/错误码.md`）+ 各检查点接入 + 诊断包带版本

| 码 | 场景 | 用户看到的提示 | 下一步建议 |
|---|---|---|---|
| E1001 | 采集源打不开 | 摄像头/文件不可用 | 换 `--index` 或检查路径 |
| E1002 | 服务端不可达 | 连不上 127.0.0.1:8000 | 跑 `egomed doctor`，查端口占用 |
| E1003 | 请求超时 | 3s 内无响应 | 看服务端日志，确认预热完成 |
| E1004 | 渲染失败 | 无法打开显示窗口 | 换 `--renderer file` |
| E3001 | 解释器缺失 | 找不到 Python | 先跑「安装环境.bat」 |
| E3002 | 依赖缺失 | 缺 opencv-python 等 | 按提示 pip 安装 |
| E3003 | 端口占用 | 8000 已被占用 | 已有实例在跑，直接附着 |
| E3004 | 权重缺失 | 找不到 yolo/sam2 权重 | 按提示拷贝到 runs/ |

**验收标准**：人为制造 3 种故障，每种都给出唯一错误码 + 一句人话 + 一条下一步；诊断包解压后可独立定位问题。

## 五、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 入口收敛破坏现场习惯 | 演示点错图标 | 旧 bat 保留转发壳；桌面只放一个快捷方式 |
| GUI 加日志面板导致界面卡顿 | 演示掉帧 | 队列 + `after()` 轮询；日志面板限 500 行滚动 |
| tkinter 依赖缺失（精简 Python） | 控制台起不来 | doctor 里前置检查，缺则提示用 `--renderer file` 的 CLI 模式 |
| 配置读写与命令行冲突 | 行为难预测 | 固定四层优先级并写进 `--help` |
| 打包踩 torch/CUDA 动态库 | 增量之外的延期 | 便携 venv 优先，PyInstaller 只作实验 |

---

## 六、明确不做

- 不做 WebSocket 推送、不做真流式 SAM2 增量、不动引擎与契约；
- 不做安装器（NSIS/Inno），便携包够用；
- 不重构现有 `client/` 内部实现——只加菜单与日志通道。
