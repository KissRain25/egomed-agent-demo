# EgoMed-Agent 错误码表（v1.1）

> 创建：2026-11-02 ｜ 更新：2026-11-03（v1.1：打通契约码）｜ 维护：闫 ｜ 关联：`egomed_errors.py`（代码形态）、`软件制作/计划_软件化实施.md` 增量 4
> 原则：**现场只认三件事** —— 唯一错误码、一句人话、一条下一步。禁止把 traceback 直接甩给用户。

## 分段

| 段 | 含义 | 典型来源 |
|---|---|---|
| `E1xxx` | 链路 / 运行期 | 采集源、服务端连接、超时、回显 |
| `E3xxx` | 环境 | 解释器、依赖、端口、权重 |

## 码表

| 码 | 场景 | 用户看到的（一句人话） | 下一步 | 代码里的判定点 |
|---|---|---|---|---|
| **E1001** | 采集源打不开 | 摄像头或文件不可用 | 换 `--source cam --index 1`，或把 `--input` 指到存在的帧目录 | `classify(FileNotFoundError/PermissionError)`；`live_console` 启动前校验输入路径 |
| **E1002** | 服务端不可达 | 连不上服务端 | `egomed.bat doctor` 看服务端那行；`netstat -ano \| findstr :8000` | `classify(ConnectionError/URLError)`；`pick_server_code()` 判定"端口没人听" |
| **E1003** | 请求超时 | 3s 内没有响应 | 看 `runs/server_log.txt` 是否还在预热（真引擎首次 60~90s） | `classify(TimeoutError/socket.timeout)`；`URLError.reason` 是超时也算它 |
| **E1004** | 回显渲染失败 | 打不开显示窗口 | 配置 `display.renderer = "file"`，结果落盘再看 | 渲染器初始化异常 |
| **E1101** | 服务端拒绝请求（4xx） | 请求被服务端拒绝（参数缺失、格式错或上传超限） | 多半是客户端 bug：核对 `session_id`、`timestamp`（毫秒整数）、文件大小（帧/音频各 ≤2MB）；用 `egomed.bat diag` 看请求原文 | 契约码 **1001** → `CONTRACT_TO_E`；无契约码时 HTTP 4xx 也归它 |
| **E1500** | 服务端内部错误（5xx） | 服务端内部错误（500） | 看 `runs/server_log.txt` 末尾的 traceback（完整异常只进服务端日志、不外泄）；用 `egomed.bat diag` 打诊断包给开发 | 契约码 **5000** → `CONTRACT_TO_E`；无契约码时 HTTP 5xx 也归它 |
| **E3001** | 解释器缺失 / 版本过低 | 找不到可用的 Python | 跑「安装环境.bat」，或设 `EGOMED_PY` | `launcher.find_python()`；Python < 3.10 |
| **E3002** | 依赖缺失 / 脚本找不到 | 缺包或仓库不完整 | 按提示 `pip install <包>`；脚本缺失则检查仓库 | `classify(ModuleNotFoundError)`；`forward_script()` 找不到目标脚本 |
| **E3003** | 端口被占用 | 多半是已有实例在跑 | 直接附着到已运行实例；要重开先结束占用 8000 的进程 | `pick_server_code()`：能连上但 `/healthz` 没过 |
| **E3004** | 权重缺失 | 找不到 yolo 权重目录 | 按 doctor 列出的路径补 `runs/yolo26_det/<模态>_*/weights` | `launcher.cmd_doctor()` 的权重目录检查 |

## 两套码：契约码 ↔ E 码（2026-11-03 打通）

**不是重复，是两层**：

| 层 | 谁在用 | 取值 | 含义 |
|---|---|---|---|
| **契约码** | 服务端 → 机器 | 1001 / 5000（其余不进 JSON） | 服务端**说了什么**（契约 §6，跨端契约） |
| **E 码** | 客户端 → 人 | E1001~E1500 / E3xxx | 客户端**该做什么**（一句人话 + 一条下一步） |

映射表（`egomed_errors.CONTRACT_TO_E`）：

| 契约码 | HTTP | → E 码 | 为什么这么映射 |
|---|---|---|---|
| `1001` | 400 | **E1101** | 参数缺失 / 格式错 / 上传超限 → 是客户端的请求有问题 |
| `5000` | 500 | **E1500** | 服务端自己崩了 → 要去看服务端日志 |

- 服务端**真会放进响应 JSON** 的契约码目前只有这两个；
  `2001/2002` 按决议 #13 只作诊断位不进 JSON，`1002/2003` 本期不可达 → **不映射**（映射了就是"永远走不到的分支"）。
- 客户端两条识别路径：
  1. `classify(exc)` —— 拿到**异常**时按类名 / 响应体判定（requests 的 `Timeout` / `ConnectionError` / `HTTPError` 都在内）；
  2. `code_from_error(err_text)` —— 拿到**错误串**时按 `[code=1001]` 这类标记翻译
     （`mock_client.post_multipart` 会把契约码带进错误串）。

> ⚠️ **2026-11-03 修掉的真缺陷**：原 `classify()` 只认 urllib 的异常类型，
> 而客户端实际用 **requests** —— `requests.exceptions.Timeout` / `ConnectionError` / `HTTPError`
> 继承的是 `RequestException` → `IOError`，**不是** builtin 的 `TimeoutError` / `ConnectionError` / `urllib.error.HTTPError`
> → 全部落到兜底 E1002「连不上服务端」。
> 现场后果：真引擎首帧慢 / 超时被报成"连不上"，提示去查端口占用 → **排查方向被带偏**。
> 现在按「类名 + 属性」识别（保持零依赖，不 import requests）：类名含 `Timeout` → E1003、含 `ConnectionError` → E1002、
> `HTTPError` → 先看响应体契约码，没有就按状态码分（≥500 → E1500，4xx → E1101）。

## 与返回码的对应

| 返回码 | 含义 | 错误码前缀 |
|---|---|---|
| 0 | 成功 | — |
| 1 | 用户取消 | — |
| 2 | 环境问题 | `E3xxx` |
| 3 | 连接问题 | `E1xxx` |
| 4 | 验收失败（回归不绿） | — |
| 5 | 功能未实现（骨架阶段） | — |

## 现场排查顺序（照这个走，不用猜）

1. `egomed.bat doctor` —— 环境类问题（E3xxx）在这一步就暴露；
2. 若 doctor 的"服务端"那行是 `[--]`：先 `netstat -ano | findstr :8000`
   - 没人听 → **E1002**，跑 `egomed.bat demo` 拉起；
   - 有人听但 `/healthz` 不通 → **E3003**，等预热或复用已有实例；
3. 语音（A2）特别说明：**HTTP 503 + `state=asr_warming` 不是错误码、也不是故障**。
   它表示 ASR *推理路径*还没预热完（首次 forward 要做 CUDA kernel / cuDNN autotune，机器首次实测 >180s）。
   客户端会自动按 10s 重试；要人工确认就等 10~60s 再试一次，**不要当 E1002 去重装环境**。
   演示前跑 `egomed.bat warmup --keep-server` 可以完全规避（见 `docs/API_CONTRACT.md` 附录 A.12）；
4. 出过一次运行后再看 `runs/diag/diag_<时间戳>.zip`（含版本清单、配置快照、服务端日志尾部、最近报告、抽样帧）。

## 维护规则

- 新增错误码：先改本表，再改 `egomed_errors.ERRORS`，两边必须同时改（`--drill` 会校验文案完整性）；
- 新增/变更**契约码 ↔ E 码**映射：改 `egomed_errors.CONTRACT_TO_E` 的同时，本表「两套码」小节也要改
  （只改一边 → 现场看到的码和文档对不上）；
- 不新增"泛泛的错误码"（如 E1000 通用失败）—— 认不出就回 `DEFAULT_CODE`，宁可少一个码也不要多十个含义重叠的码。
