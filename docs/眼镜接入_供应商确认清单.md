# 智能眼镜选型：给供应商的确认清单（N34）

> 用途：**采购/借样机前**先问清这 5 个问题。答案直接决定我们的架构能不能落地 ——
> 问清的成本是 10 分钟，问不清的代价是整个实时链路要重新设计。
> 配套：`docs/端到端流程设计.md`（眼镜端零智能，计算全在服务器）、`docs/决策记录.md` D2/D7。

## 一、必须问清的 5 个问题（按重要性排序）

### Q1　能不能拿到**实时原始帧**？通过什么接口？

| 要问到 | 为什么关键 |
|--------|-----------|
| 是否提供**实时帧回调 / 取流接口**（而不是只能"投屏"或"拍照存文件"） | 我们的 A1 链路是"每帧上传服务器推理"，**若拿不到逐帧数据，整条链路不成立** |
| 帧率、分辨率、像素格式（RGB/BGR/YUV？） | 决定是否需要转换；也决定客户端压缩前的负载 |
| **端到端延迟**（采集到回调） | 我们的预算是 A1 P95 ≈500ms，眼镜这一跳不能吃掉太多 |
| 能否同时取帧 + 录音 | A1（画面）与 A2（语音）是两条链路，要并行 |

> **Q1 是唯一的一票否决项。** 如果只能"投屏/拍照"，我们就要改成"手机或外接摄像头取帧、眼镜只做显示"（见 §四）。

### Q2　能不能**自定义渲染 overlay 到镜片视野**？

| 要问到 | 为什么关键 |
|--------|-----------|
| 能否在我们算出的**分割掩膜 / 文字 / 提示语**之上做显示 | 回显层（N35 `Renderer`）的形态由它决定 |
| 显示方式：全屏画面？叠加在实景上？分区域（一侧影像、一侧结果）？ | 决定"看屏幕影像 + 看结果"的布局 |
| 视场角 / 可视区域尺寸 / 是否支持透明度与颜色 | 掩膜在亮背景 vs 暗背景下是否看得清 |
| 是否支持**逐帧刷新**（而不是固定 UI 模板） | 分割结果是每帧变化的 |

### Q3　SDK 的形态与约束？

| 要问到 | 为什么关键 |
|--------|-----------|
| 平台与语言：Android / Linux / Windows / Unity / C++ / Python？ | 决定 `GlassesAdapter` 怎么写（当前是 Python 侧适配） |
| 开发包是否完整（文档、示例、模拟器） | 没有模拟器就只能在真机上调 |
| 是否要求**特定固件版本 / 开发者模式 / 签名** | 影响交付流程与演示稳定性 |
| License / 授权费用 / 是否允许商用与二次开发 | 医疗场景尤其要注意 |
| 是否支持**后台常驻** | 演示时不能前台一直点着 |

### Q4　音频能力？

| 要问到 | 为什么关键 |
|--------|-----------|
| 麦克风数量（是否阵列）与**远场拾音**能力 | 我们已实测：**环境闲聊会被 ASR 编成器官序列**（失败案例 7）→ 远场更放大这个问题（N37 要做门槛） |
| 能否直接拿到 **16 kHz 单声道 PCM/WAV** | 我们的 A2 契约是 `wav 16kHz 单声道 ≤5s ≤200KB` |
| 是否自带降噪 / 回声消除；能否关闭 | 我们倾向"原始音频 + 服务端门槛"，需要可关闭 |
| 录音时能否同时取帧 | 同 Q1 |

### Q5　佩戴与续航的**实测参数**？

| 要问到 | 为什么关键 |
|--------|-----------|
| 重量 / 是否可长时间佩戴 | 演示与试用时长 |
| 电池续航（**边取帧边录音**这种负载下） | 官方标称往往按"待机"算 |
| 发热与降频表现 | 长时间跑会不会掉帧 |
| 能否**边充边用**（有线供电） | 桌面演示建议直接插电 |
| 佩戴稳定性 / 是否需配镜片度数 | 第一人称抖动是我们关注点（真机才会暴露） |

## 二、加分项（次要，但会踩坑）

- **校准/佩戴检测接口**：能否读到"是否戴好、是否对准"（我们要做引导式校准 N36）
- **网络**：WiFi 频段（建议 5GHz）、是否支持蓝牙、断线重连行为
- **数据合规**：是否允许视频/音频离开设备（我们目前是局域网私有部署）
- **消毒/防护**：医疗场景是否需要可擦拭表面
- **配套**：备件、保修、**开发样机借用**、交付周期

## 三、拿到答复后的三种走向

| 供应商答复 | 我们的对策 | 工作量 |
|-----------|-----------|--------|
| **能取实时帧 + 能自定义渲染** | 写 `MyGlassesAdapter`（Q1 回调 → 队列）+ 实现 AR `Renderer` | 约 **1~2 周**到"眼镜上跑通" |
| 能取实时帧 + **只能显示固定 UI** | 回显改**外接屏/平板**（就是 N47 "半真"链路），眼镜只负责采集 | 约 **2~3 天** |
| **只能投屏/拍照** | 采集改**手机 / 外接 USB 摄像头**，眼镜只做显示（当前模拟方案已经是这个形态） | **0 天**（已在跑） |

> 换句话说：**Q1 决定可行性，Q2 决定"看起来像不像 AR"。** 两者都要最好；只有 Q1 也够用。

