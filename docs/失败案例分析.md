## 案例 1：坏帧“装懂” —— 画面糊了也返回分割结果

| 项 | 内容 |
|----|------|
| **现象** | 早期假实现对模糊/全黑画面**回传原图当 overlay**，还带着上一帧的会话状态（`modality="ACDC (MRI 心脏)"`、`target="LV cavity"`）。医生会看到画面突然从“有标注”变成“原图”，视觉上**闪跳**；且系统谎报“我识别到了” |
| **根因** | ① 实现里没有“画面不可用”分支；② 把“参数错/无内容”当成错误码 2001 走 error 路径，而契约规定它是**正常业务状态** |
| **对策** | 契约 A1 边界情况 1：返回 `status:"ok"` + `modality/target/overlay` 全空 + `message:"画面里没检测到目标，请对准屏幕"`；客户端收到空 overlay 时**保留上一帧画面**（防抖），不黑屏不闪跳 |
| **现状** | ✅ 已修并复验：mock 套件坏帧 5/5 返空（`runs/acceptance/20260918_*`）；真引擎同语义 |
| **衍生问题** | 假实现的坏帧判据（亮度/对比度/**拉普拉斯方差**）**对分辨率敏感**：同一张 ACDC 帧，原图 lapvar=28（判“模糊”）、客户端压缩到 1280 后 lapvar=136（判正常）→ 已登记 **N16**（判定前统一缩到固定尺寸再算）→ **✅ 2026-09-28 已修**：判定前长边归一化到 640 并重调阈值，同一画面各分辨率/压缩变体判定一致（区间内 15/15），原图直发坏帧 5/5、正常帧 5/5 |

## 案例 2：跨模态歧义 —— “左心室”在 MRI 和超声里都存在

| 项 | 内容 |
|----|------|
| **现象** | 医生说“帮我分割左心室”，服务端返回 `target=""` + `need_confirm=true` + `candidates=["LV cavity","Left Ventricle"]`，后续帧全部提示“请先告诉我要分割哪个器官” |
| **根因** | ACDC(MRI) 的类别是 `LV cavity`，CAMUS(超声) 是 `Left Ventricle`——**同一个中文词映射到两个模态的不同类别**，模型/规则都无法单方面决定 |
| **对策** | 契约边界情况 2：**不猜**，返回候选让医生澄清；客户端显示 message → 医生补一句更具体的指令（如“左心房”“超声左心室”）|
| **现状** | ✅ 契约与实现一致（`need_confirm` 正确触发）；⚠️ 但客户端此前没有“需澄清”提示 → 已在 `live_client.py` 补齐（HUD 显示候选提示） |
| **启示** | 医学词表天然存在**跨模态同名**；用“主动澄清”换取正确性，比猜一个更好 |

## 案例 3：ASR 幻觉复读 —— cmd_02 转写 20 秒乱码

| 项 | 内容 |
|----|------|
| **现象** | “把右心室腔标出来”偶发转写出复读词表内容（“右心室 右心房…肝肝肝肝”），耗时 8.8~9.4s，脱离服务端单独跑甚至 **20.02s + 全乱码**；同环境其它句只要 0.46s |
| **根因** | 为治同音错字引入的 `hotwords`/`initial_prompt`（器官词表偏置）在**音频含糊**时把解码推向“猜词表” → 自回归解码陷入**重复生成**（复读循环） |
| **对策** | 三层刹车：① 解码侧 `condition_on_previous_text=False` + `repetition_penalty` + `no_repeat_ngram_size`；② 输出侧 n-gram 重复率/连续同字检测；③ 逐段时间兜底（首次 4s、重试 2.5s）；检出异常→降级重试→**返空串让医生重说** |
| **现状** | ✅ **8.8s→1.2s 且文本正确**；连跑 10 次全对；模块自测 25/25、real 套件 10/10（契约 A.11.1） |
| **启示** | **性能优化会长出新故障**：提示词带来准确率，也带来幻觉；必须给优化配“刹车”，并定义**降级策略**（宁可返空，不可给错） |

## 案例 4：小器官被误检过滤“误杀” —— 脾脏永远检不到

| 项 | 内容 |
|----|------|
| **现象** | Amos(CT) 病例 100 目标脾脏：**0/8 帧检出**、Dice=0；而该病例标注确实存在（1132 px） |
| **根因** | 引擎的误检过滤 `min_area_ratio=0.001`（占帧面积 0.1%）**大于小器官本身的面积占比**（脾脏 1132 / 3 980 000 = **0.028%**）→ 检测框被当“小面积误检”丢弃。ACDC 心肌占 0.18% > 0.1%，所以此前未暴露 |
| **对策** | 关闭过滤（`min_area_ratio=0`）后同病例 **8/8 检出、Dice 0.705±0.027、IoU 0.545**；建议按模态/目标尺度设阈值（如 Amos 用 0.0002）或改用相对期望尺寸的自适应阈值 |
| **现状** | ✅ **2026-09-28 已修（N18）**：服务端按模态传阈值（CT 腹部 `min_area_ratio=0.0001`、其余维持 0.001），**引擎自身不改**（红线 4）。离线 A/B（同一批帧只改阈值）：脾脏 病例101 **0/6 → 6/6 检出 + 6/6 分割**；十二指肠 病例102 **0/6 → 6/6**。在线实测：脾脏/十二指肠均**首帧即出结果（5/5）**；ACDC/胸片/息肉无回归；real 套件 11/11。详见 `决策记录.md` **D13** |
| **启示** | 阈值型过滤器有**尺度依赖**：在小目标上“过滤误检”与“过滤真目标”无法用同一个绝对阈值区分 |

## 案例 5：ASR 同音短词与英文指令（50 句扩样暴露）

| 项 | 内容 |
|----|------|
| **现象** | 52 句评估（TTS 合成）：**字准率 86.6%**、NLU 解析 **43/49（88%）**；失败集中在 —— “分割胃”→转写“分割位/一胃”、“子宫”→“指宫”、“胰腺”→“一线”；5 句**英文指令**被强制中文转写（`language="zh"`）成“分割指令，” |
| **根因** | ① 单字/双字同音词（胃/位、胰腺/一线）在强词表偏置下仍可能被常用词抢走；② 实现**固定中文**（契约面向中文医生语音），英文不支持；③ TTS 合成语音与真人发音差异也会放大错误 |
| **对策** | ① 词表与 prompt 可继续扩充（含“胃”“胰腺”等短词的优先偏置）；② 明确**语言边界**：英文指令走文本接口或后续多语言模型；③ 医疗场景建议**先澄清再执行**（低置信时不猜） |
| **现状** | ⚠️ 记录为已知限制；英文指令不在当前契约范围内（`API_CONTRACT.md` A2 以中文医生语音为主） |
| **启示** | **短词/同音词是中文医学 ASR 的顽疾**；词表偏置能大幅改善但不能消灭，必须配合“澄清/重说”交互 |

## 案例 6：批处理内核 vs 在线需求 —— “越用越慢”

| 项 | 内容 |
|----|------|
| **现象** | 客户端连续发帧时，A1 延迟随会话增长：2 帧 1.36s → 6 帧 3.39s → 满窗 3.8s，突破 3s 超时（12 帧内超时 7 次）；且**每个会话第一帧必然返回空** |
| **根因** | ① 服务端每次请求对**整个滚动窗口（10 帧）**重跑“检测+SAM2 分割+跟踪”，计算量随窗口线性增长（继承自离线批处理流程）；② 时序滤波 `min_occurrence=2` 要求“连续 2 帧出现”，单帧窗口必被过滤 |
| **对策** | ① 只对**最新帧**推理（窗口 10→1），计算量变常数；② 显式 `min_occurrence=1` 让首帧即有结果。**并用同一批帧量化了精度代价：Dice 0.394→0.403（≈0）** |
| **现状** | ✅ P95 **3035ms → 491ms**、超时 **7 → 0**、首帧即有结果（`联调发现…md §六之二`） |
| **启示** | **复现来的算法默认“数据整段给”，搬进实时链路必须先拆掉这个假设**；改完要用指标证明“精度没有变差” |

## 案例 7：环境闲聊被“翻译”成器官序列 —— 领域词表偏置的第二种幻觉

| 项 | 内容 |
|----|------|
| **现象** | N4.5 现场（手机当镜头）开着麦克风时，环境里的闲聊/动静被 A2 转成**器官词沙拉**：「左心室 右肝脉 胰腺 子宫 左肾 胱脊 胸脊」「左心室 右肺 胱腺 子宫 脾脏 胰腺」「右心室 右肺 胰腺 脾脏 胱腺」「吃吧」「晚安」（振幅只有 0.003~0.03，明显不是对着麦克风说的指令） |
| **根因** | 与案例 3 同源但**表现形式不同**：医学领域 `initial_prompt`+`hotwords` 把解码器强偏置到**器官词表**上，输入却是极短/含糊/非指令音频 → 模型不从"这句话是什么"出发，而是"在词表里挑几个词填满" → 输出语法上像指令、语义上纯编造。**复读检测抓不到**（无重复 n-gram、无连续同字） |
| **对策** | ① **现场演示时不开麦克风**（防抖/分割测试与语音切换分开测）② 客户端侧对**低振幅段**（峰值 < ~0.01）直接丢弃、不送 A2 ③ 服务端侧：解析要求"目标词必须是短句主体"，无动词/多处器官并列时**返空**而非执行（例：5 个器官并列明显不是一次指令）④ 保留 N1 三层防护（复读类幻觉） |
| **现状** | ⚠️ 部分缓解：解析失败时服务端返 `需澄清` 且**不改会话目标**（本次多数如此，设计顶住）；但**并列多器官时会真的切目标**（实测「右心室 右肺 胰腺 脾脏 胱腺」→ 目标切成 `RV cavity`）。②③ 尚未实现，已记入待办 |
| **启示** | **"文字像指令"不等于"用户下了指令"**：领域词表优化必然带来"词表泄漏"型幻觉；除了防复读，还要防"**没有指令意图却被解成指令**"——要么在输入端设门槛（振幅/时长），要么在输出端设门槛（语法结构/目标数量） |

## 汇总：七类失败的共性与应对原则

| 共性 | 应对原则 |
|------|---------|
| 阈值/滤波的**隐式前提**被使用场景破坏（案例 1、4、6、7） | 阈值必须**尺度/分辨率归一化**；滤波要允许“样本不足”的降级路径；输入侧设门槛（振幅/时长/构图） |
| 模型**会说谎**（幻觉、编造、强制语言、词表泄漏）（案例 3、5、7） | 宁可**返空 + 澄清**，也不给错误结果；输出侧要有独立校验（复读检测 + 意图检测） |
| **语义歧义**无法靠模型单方决定（案例 2） | 主动**澄清交互**（`need_confirm` + 候选） |
| 离线算法的假设与在线需求冲突（案例 6） | 在线化是**重新设计**而非“把代码搬上线”；改动用**指标**验证代价 |
| **"文字像指令"≠"用户下了指令"**（案例 7） | 领域词表优化必然带来词表泄漏型幻觉；既要防"复读"，也要防"**无意图被解成意图**" |

> 答辩一句话总结：**“我们的失败都被量化并给出了对策——坏帧返空不闪跳（M3 真机实证）、歧义主动澄清、幻觉三重刹车、小目标阈值按模态自适应、批处理改增量推理（精度代价实测 ≈0）、领域词表偏置的第二种幻觉（环境闲聊被编成器官序列）连输入门槛一起设。”**
