### T1（P0）N23 并发超时清零　☐

**目标**：A2/A1 并发偶发超时 **1.7% → 0**

**已知线索（别重复走）**

1. 现场实测 2026-09-28（M3）：A2/A1 并发时偶发超时 **1.7%**，已登记、未定位
2. **客户端侧线索**：`client/live_client.py` 里 A1（发帧）与 A2（语音）**共用同一个超时** `--timeout`（默认 3.0s = 契约 `mc.TIMEOUT`）；正常 A2 为 **499~817ms**，但 **ASR 与分割推理抢 GPU 时可能越过 3s**
3. **待你判断的服务端侧**：A2（ASR）与 A1（推理）是否在同一线程池 / 同一资源上互相阻塞

**步骤（先量后改）**

1. **先量** —— 用混合负载工具 `client/mixed_load.py`（闫已交付，2026-10-08）：
   ```
   python client/mixed_load.py --frames 400 --audios 100 --threads 5
   ```
   - 它会**先自动设好 target**（没 target 时服务端不跑推理，压不出争抢），再先测**单流基线**、后测混合负载
   - 报告落盘 `runs/mixed_load/<时间戳>/report.md`（含统计表、失败明细、判定提示）
   - 对照组：`--frames 200 --audios 0`（只 A1）、`--frames 0 --audios 100`（只 A2）
   - 记录：超时次数、每次超时的 `elapsed_ms`、失败请求是 A1 还是 A2
2. **定位** —— 从服务端日志确认超时请求卡在哪一段（排队 / 推理 / ASR）
3. **再改**（候选方向，任选并说明理由）：
   - a. A2 与 A1 **分离超时**（A2 放宽，A1 不动）
   - b. A2 与 A1 **排队策略分离**（语音是用户主动动作，优先级更高）
   - c. **ASR 串行化 / 独立线程池**，避免与推理抢资源
4. **复测**同一命令，给改前 / 改后对照

**验收标准**：同命令同参数下 **超时 0**（500 次混合请求）

**要报的**：① 超时率 1.7% → ?　② 超时请求的日志片段（含 `elapsed_ms` 与阶段）　③ 改了哪几处 + 是否触碰接口（应为"否"）　④ `回归.bat` 结果

**目标**：客户端不再"盲等 60~90 秒"

**改哪些文件**：`server/api.py`

   {"status":"ok","sessions":N,"real_engine":true,"state":"warming"|"ready"}

**验收标准**：预热期 / 就绪后 `/healthz` 两态可区分；预热日志按阶段可见；`回归.bat --suite mock` = **8/8**

### T9（P0，新增）A1/A2 分段耗时日志　☐

**为什么加这条**：`server/api.py` 现在 **A1 只有"总耗时"一行**（`_log_frame`，L196），**A2 成功请求完全没有日志**（L556~595 全是 return）→ **T1 的"A2 超时"在服务端日志里看不到**，无法定位卡在哪一段。这是 T1"先量后改"的前置。

**改哪些文件**：`server/api.py`（只加日志，**不动任何响应字段**）

**做什么**

1. **A1 分段**（在 `_handle_frame_real` 里分别计时）：
   - `wait_ms`：排队等待（`submit_frame` 里等条件变量的时间 —— 体现"被新帧覆盖/被别的请求占着"）
   - `infer_ms`：推理（`processor(...)`）
   - `encode_ms`：overlay 压缩/编码
   - `total_ms`：合计（现有 `elapsed_ms`）
   - 日志格式（沿用现有一行风格，追加字段）：
     `session=... | frame=... | modality=... | target=... | wait=..ms infer=..ms encode=..ms total=..ms | ok`
2. **A2 补日志 + 分段**（现在一次都没记）：
   - `read_ms`（音频读入）/ `asr_ms`（转写）/ `nlu_ms`（`parse_target`）/ `total_ms`
   - 结果字段照旧记录：`text`、`target`、`need_confirm`、`status`
   - 日志：`session=... | audio=<文件名> | text=... | target=... | read=..ms asr=..ms nlu=..ms total=..ms | ok`
3. （可选）A1 被 latest-wins 覆盖的帧也记一行 `dropped`，便于看清丢帧率

**验收标准**

- 压一次混合负载后，`runs/server.log` 里**每个 A1/A2 请求都有一行**，且**含分段字段**
- 能据此判断超时（或慢）卡在哪一段

**要报的**：改后的两行日志样例（A1 一行、A2 一行）+ `回归.bat` 结果（mock 8/8）
