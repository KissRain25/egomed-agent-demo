# 半真链路现场操作（N47）

> 目标：不用智能眼镜，用**手机 IP Webcam 当镜头** + **另一块屏当"病人屏"**，
> 把"眼镜 -> 服务器 -> 回显"这条链路**真机跑一遍并留证**，用于汇报现场演示。
> 现状：`client/live_client.py` 的网络流采集源**已就绪**（D14 断流自动重连），
> N4.5 在 2026-09-28 已经跑通过一次；N47 要做的是**在当前版本上复录并留档**。

## 一、摆位（**这一步最容易出错，N4 踩过**）

**原则：镜头与影像屏必须是两块东西。** 笔记本自带摄像头在屏幕上方，**拍不到自己的屏幕**。

### 方案 A（推荐，现场最稳）：手机当镜头，笔记本屏幕当病人屏

1. 笔记本屏幕全屏显示一张医学影像（用现成样例图即可，见下方命令）
2. **手机装 IP Webcam**（Android 应用），手机**镜头对准笔记本屏幕**
3. 手机与笔记本连**同一 WiFi**
4. 手机上打开 IP Webcam，记下它显示的地址（例如 `http://192.168.1.23:8080/video`）

### 方案 B：手机当病人屏，另一台设备当镜头

1. 手机全屏显示影像（当"病人屏"）
2. 另一台设备（平板/另一部手机）当镜头对着手机屏
3. 那台设备装 IP Webcam，用它的地址

## 二、跑起来（三条命令）

### ① 起真引擎服务端（**保留不关**，供客户端连）

```powershell
python scripts/demo_day.py --quick --keep-server --port 8030
```

看到 `[OK] 服务端保留运行中` 即可（这个脚本顺带把预检与 ASR 预热都做了）。

### ② 确认手机视频流通

浏览器打开 `http://<手机IP>:8080/video`，能看到画面 = 通；打不开 = 看第五节。

### ③ 跑客户端（采集 -> 上传 -> 分割 -> 回显）

```powershell
python client/live_client.py --source url --input http://<手机IP>:8080/video `
    --url http://127.0.0.1:8030 --fps 3 --source-fps 10 `
    --audio data/samples/audio/cmd_03.wav `
    --save-frames --out runs/half_real/<时间戳> --duration 120
```

- `--audio`：**先说后看**（A2 设目标"myocardium"），符合契约语义
- `--fps 3`：采集帧率（半真链路用 3fps 更接近真实眼镜；别开 5fps above 手机 MJPEG 的能力）
- `--save-frames`：抽样帧落盘（**留证用**）
- `--out`：产物目录（报告 + 帧 + 统计）
- `--renderer window`（默认）会弹回显窗口；`--no-show` 无头跑（适合只留数据）

## 三、留证清单（汇报要用的四样）

| 要什么 | 从哪来 |
|---|---|
| 端到端延迟与帧率统计 | `--out` 目录里的 `report.md`（含 P50/P95、刷新率、检出帧数） |
| 回显画面截图 | `--out` 目录里的抽样帧（`--save-frames`） |
| 现场照片 | 手机 + 笔记本的摆位照片（证明是真机链路不是放片子） |
| 录屏 | Windows 自带录屏（`Win+Alt+R`）或 OBS；**必须录**，现场万一崩还有兜底 |

## 五、失败排查（按 N4.5 的实际踩坑顺序）

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 浏览器打不开 `/video` | 手机与电脑不在同一 WiFi / IP 变了 | 手机上重新看 IP；关掉 VPN |
| 能连上但画面全黑 | 手机镜头没对准屏 / 被遮挡 | 重新摆位（方案 A 第 2 步） |
| 画面有但"未检测到目标" | 拍到的不是影像屏，或影像选错 | 确认笔记本屏幕上确实是 `data/samples/acdc` 里的图 |
| 首帧很慢（几十秒） | 服务端还在预热引擎 | 已在步骤 ① 用 `demo_day.py --keep-server` 预热过；或看 `/healthz` 的 `state` |
| 语音没反应 | `--audio` 路径不对 / ASR 未就绪 | 用绝对路径；`/healthz` 看 `state=ready` |
