### 4.2 服务端 ↔ 客户端 字段一致性（实测，非人工核对）

> 起因：闫问「服务端和客户端互通性怎么样，字段一致吧」。三方对照 + 逐分支实测。

| 对照项 | 字段数 | 结论 |
|---|:--:|---|
| 契约 §4 A1 响应 | 11 | 基准（status / session_id / timestamp / modality / target / overlay / message / need_confirm / candidates / elapsed_ms / frames_processed） |
| 契约 §4 A2 响应 | 8 | 基准（status / session_id / text / target / modality_hint / need_confirm / candidates / message） |
| 服务端实际返回（假实现 5 分支 + 真引擎 4 分支） | 11 / 8 | ✅ **逐字段对齐**（修掉一处后，见下） |
| 客户端代码实际会读 | 9 + 2 | ✅ **服务端全部提供，无断链**（9 个成功响应字段 + `state`/`retry_after_s` 两个 503 字段） |

- **抓到并修掉的一处真不一致**：**空文件（边界 1）分支只给 9 个字段** ——
  `_boundary1_payload()` 被 `post_frame` 提前 return，绕过了统一补 `elapsed_ms`/`frames_processed`；
  已补齐（契约 §4 的 A1 就是 11 个字段，客户端不读但第三方实现会按契约对不上）。
- **新增实测脚本 `client/test_field_alignment.py`**：契约字段清单**从 `API_CONTRACT.md` 的 JSON 示例解析**
  （不硬编码，契约改了自动跟随），逐分支比对「缺字段 / 多字段 / 私有字段泄漏 / 客户端读不到」，已接入 `regress`。
- **实测结果 10/10 PASS**（假实现 M1~M5 + 真引擎 R1~R4 + 503 响应体）；mock 与真引擎两条路径字段集合完全一致。
- **附注（不是不一致）**：服务端给了 `session_id` / `timestamp` / `frames_processed` / `modality_hint`，
  **客户端当前一个都没读** —— 其中 `modality_hint`（A2 建议模态）与 `frames_processed` 有信息量，
  要不要用起来属客户端的活，本轮未动。
