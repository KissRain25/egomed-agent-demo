## 2. 逐周明细

### W2（10-12 ~ 10-16）

#### C1 `api.py` 合并（方案 A）—— **本周第一优先**
**背景**：队友 10-10 交了 `server/api.py`（**T9 分段耗时日志 / T2 预热体验 / T10 `/healthz` 资源字段**，三项本身做得好），但他的底本**停在 9-28 之前**，缺主线已验收的三项：

| 主线已有 | 他的文件 | 直接覆盖的后果 |
|---------|:---:|------|
| **N16 坏帧归一化**（`BAD_NORM_DIM=640`，阈值 20/120/12000） | ❌ 无 | 旧阈值对分辨率敏感 → 原图被判"模糊" |
| **P2.10 overlay 规格压缩**（`_encode_overlay` / `OVERLAY_MAX_*`） | ❌ 无 | 真引擎图 723KB~1.28MB/帧 原样回传 |
| **P2.9 `timestamp` 必填校验**（`_parse_timestamp`） | ❌ 无 | 契约 §4 校验丢失 |

**做法**（例外流程，先例见 `决策记录.md` **D10**）：
```
备份 server/api.py.bak-1011
  → 把 T9 / T2 / T10 移植到主线（保留 N16 / P2.9 / P2.10 / P2.12）
  → 跑 回归.bat（mock 8/8 + real 11/11）
  → 登记 docs/工作日志.md
  → 通知李（并把合并后的最新 api.py 发他）
```
**验收**：回归双套全绿；`/healthz` 含 `state` / `rss_mb` / `gpu_mem_mb`；A1/A2 响应**字段与契约完全一致**（私有键 `_wait_ms`/`_encode_ms`/`_dropped`/`_timing` 必须弹出）。
**不采纳（保留主线口径）**：旧坏帧阈值 ｜ `_overlay_b64` 直编 ｜ 他的 `WINDOW_SIZE=10 + 单帧目录` 变体（主线是 `WINDOW_SIZE=1`，效果等价、代码更简）。
**★ 待决策**：他顺手做的「**检测失败复用上一帧 overlay**」（`session.last_overlay_b64`）—— 建议采纳（服务端侧兜底），但要一并定"客户端如何反应"，避免与客户端"不动 `last_result`"重复。
