# 指标：分割精度 —— 在线（窗口=1）vs 离线（批处理）

> 日期：2026-09-25 ｜ 工具：`client/eval_segmentation.py`（新增）｜ 关联：总计划 **N8**（量化指标）
> 目的：量化「为修 N13 把窗口 10→1（放弃 SAM2 跨帧传播）」的**精度代价**，并顺带评估引擎参数对小器官的影响。

---

## 一、方法

| 项 | 做法 |
|----|------|
| 数据 | `data/ACDC`（MRI 心脏，标注值 `myocardium=2`）、`data/Amos`（CT 腹部，`spleen=1`） |
| 帧选取 | `--auto-start`：自动定位第一个**「有标注且 YOLO 可检出（conf≥0.3）」**的帧，两模式评估同一批帧（每例 8 帧） |
| 离线模式 | 调用 `egomed_demo._segment_target`（原 demo 批处理路径，`min_occurrence=2`、`min_area_ratio=0.001`） |
| 在线模式 | 逐帧走 HTTP：A2 设目标 → 每帧 A1 → 取服务端 `runs/stream/<sid>/seg/masks/*.png`（与真实客户端同链路，含客户端压缩） |
| 指标 | Dice = 2‖A∩B‖/(‖A‖+‖B‖)，IoU；预测掩膜上采样到标注尺寸（在线掩膜来自 1280 长边的压缩帧） |
| 跳过规则 | 标注为空的帧不计入（数据集许多帧本无该目标标注），并单独报告跳过数 |

## 二、结果（ACDC / myocardium，4 个病例 × 8 帧）

| 病例 | 离线 Dice | 在线 Dice | 差值（在线−离线） | 离线 IoU | 在线 IoU |
|------|----------|----------|------------------|---------|---------|
| 1 | 0.377 | 0.396 | **+0.019** | 0.233 | 0.247 |
| 10 | 0.573 | 0.567 | −0.006 | 0.402 | 0.396 |
| 11 | 0.331 | 0.301 | −0.030 | 0.199 | 0.177 |
| 12 | 0.294 | 0.346 | **+0.052** | 0.173 | 0.210 |
| **均值** | **0.394** | **0.403** | **+0.009** | 0.252 | 0.258 |

**结论 1：在线化的精度代价 ≈ 0。**
4 个病例差值在 −0.030 ~ +0.052 之间摆动、均值为 +0.009（在线略优）——**没有系统性下降**。
合理的解释：窗口=1 时每帧独立检测+分割，避免了 SAM2 长程传播的**漂移累积**；而离线靠传播，稳定帧更好、漂移帧更差。

**结论 2：延迟同时大幅下降**（同批帧实测）：在线 均值 **446ms / P95 502ms**（ACDC 心肌），而离线批处理为 **0.55~0.68 s/帧**且**必须等整段结束**才能出结果——实时场景下不可用。

> 备注：Dice 绝对值偏低（0.29~0.57）是因为**心肌是环形薄结构**、且标注来自 1728×2304 的大图上采样，边界误差被放大；衡量“在线 vs 离线”的相对比较不受影响。

## 三、附带发现（引擎参数）：误检面积过滤会误杀小器官

**现象**：`data/Amos` 病例 100、目标 `spleen`

| 配置 | 结果 |
|------|------|
| 引擎默认（`min_area_ratio=0.001`，即帧面积 0.1%） | **检出 0/8**，Dice 0 |
| 关闭过滤（`min_area_ratio=0`） | **检出 8/8，Dice 0.705±0.027，IoU 0.545** |

**根因**：该病例脾脏标注仅 **1132 px / 3.98M px = 0.028%**，**低于 0.1% 的过滤阈值** → 被当成误检丢弃（在线/离线两条路径都会丢）。
ACDC 心肌标注约占 0.18% > 0.1%，所以没受影响——这也解释了为什么之前只在 Amos 上暴露。

**影响与建议**：
- 对小器官（脾脏、肾上腺、十二指肠等）**默认过滤阈值过严**；建议按模态设置（如 Amos 用 0.0002）或改为“相对目标期望尺寸”的自适应阈值
- 契约层面无需改字段；属**服务端/引擎参数**问题（`min_area_ratio` 默认值），建议登记为 **N18**，由李或闫评估后统一调整

## 四、方法学教训（评审时会被问到的点）

| 坑 | 教训 |
|----|------|
| 只看前 8 帧就评估 → Dice 全 0 | 数据集**许多帧本来没有标注**；评估必须筛选“有标注”的帧 |
| 有标注 ≠ 可检出 | `--auto-start` 必须同时满足“有标注 + YOLO 可检出（阈值与引擎一致 0.3）” |
| 在线掩膜 960×1280 vs 标注 1728×2304 | 预测掩膜需**上采样对齐**后再比（在线掩膜来自客户端压缩帧，这是契约规定的上传规格） |
| 部分 PNG 读出来是 (h,w,1) | 掩膜/标注读取后需统一压成二维，否则广播报错 |
| 引擎默认阈值 0.3 vs 自测用 0.25 | 评估用的筛选阈值必须与**生产链路一致**，否则选到管线检不到的帧 |

## 五、复现命令

```powershell
# 服务端 --real 启动并预热完成后
python client\eval_segmentation.py --modality "ACDC (MRI 心脏)" --case 10 --target myocardium --frames 8 --mode both --auto-start
# 小器官（关闭面积过滤的对照实验）
python client\eval_segmentation.py --modality "Amos (CT 腹部)" --case 100 --target spleen --frames 8 --mode offline --auto-start --min-area-ratio 0
```
报告落盘：`runs/metrics/<时间戳>/report.md`（含逐帧明细）+ `result.json`
