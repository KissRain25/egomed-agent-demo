# AI 协作规范（本项目如何与 AI 助手配合）

> 创建：2026-09-20 ｜ 维护：闫 ｜ 状态：v1.0
> 适用：EgoMed-Agent 项目中，与 AI 助手协作的全部场景
> 配套：任务表 `总计划.md` ｜ 断点 `工作日志.md` ｜ 接口规则 `API_CONTRACT.md`（v1.0 冻结）｜ 决策 `决策记录.md`

---

## 一、为什么需要这份规范

AI 对话是**易失**的（上下文会被截断、跨会话不继承），而项目是**长期**的。若没有规则，会出现三类典型损失：

1. **结论蒸发**：对话里定好的方案，下次开新会话全忘了，重复讨论
2. **越权改动**：AI 顺手重构/改接口/加依赖，打破 v1.0 冻结纪律
3. **假绿交付**：AI 说"已完成"，实际没跑验收，问题在联调时才暴露

本规范就是针对这三类损失的约束与流程。

---

## 二、三条基本原则

| 原则 | 含义 | 落到操作 |
|------|------|---------|
| **文档即真相** | 只有写进 `docs/` 的才算数，对话里的结论等于没发生 | 任何决定 5 分钟内落盘（见第五节） |
| **改动必绿** | 没有实测证据的"完成"不算完成 | 每次改动跑对应验收，把**实测数字**写进汇报 |
| **最小授权** | AI 只做被明确要求的改动，不做"顺手优化" | 红线清单见第四节 |

---

## 三、上下文恢复机制（每次会话开局）

**AI 开局自动读**（已写入 AI 持久记忆，无需提醒）：

```
1. docs/工作日志.md        ← 断点：上次干到哪、下一步是什么
2. docs/总计划.md          ← 任务表：当前活跃的 N 项与验收标准
3. docs/API_CONTRACT.md    ← 接口规则（涉及接口时）
4. 相关代码文件            ← 改动前必读，不凭记忆改
```

**用户只需一句话**：`读工作日志继续` 或 `开始 N4`。

**会话收尾（AI 负责）**：把本次结论追加到 `工作日志.md`，勾 `总计划.md` 状态，必要时登记契约/决策变更。

---

## 四、授权边界（红线清单）

**AI 不得自行做以下任何事**（除非用户当次明确要求）：

| # | 红线 | 原因 |
|---|------|------|
| 1 | 修改接口字段/路径/错误码 | 契约已冻结 v1.0，变更须走 v1.x 流程（提出→确认→更新文档→群通知） |
| 2 | 修改 `server/**`（李的代码） | 文件归属硬约定；如确需改，由闫确认后改并备份 `.bak-<日期>`，同时告知李 |
| 3 | 新增第三方依赖 | 会破坏可复现性；需先确认环境与版本 |
| 4 | 修改 `scripts/` 下现有引擎（SAM2/YOLO/nl_parser/asr_engine） | 只允许 `import` 复用；新增文件可以 |
| 5 | 删除数据、权重、既有报告 | 不可逆；测试现场只清理自己启动的进程 |
| 6 | 执行破坏性 git 命令（force push、hard reset、改 config） | 数据安全 |
| 7 | 提交大文件/数据集/权重到仓库 | 仓库体积；`.gitignore` 已排除 `data/ runs/ weights/` |
| 8 | 为"让测试通过"而绕过或放宽验收标准 | 那等于把 bug 藏起来 |

**允许自主做的**：新建文件、读任何文件、跑只读命令与验收脚本、按规范落盘文档、在 `client/` 内实现任务。

**遇到不确定时**：先按最合理假设继续，并在汇报里**显式标注假设**；只有真正阻塞才停下来问。

## 五、标准工作流程（每个任务照这个走）

```
① 确认任务   → 从总计划取 N 项，明确"验收标准"（没有标准就先补）
② 读代码     → 改动前必读文件现状，不凭记忆编辑
③ 小步改动   → 优先新增文件/局部修改，避免大范围重写
④ 跑验收     → 模块自测 + 相关验收套件，记录实测数字
⑤ 落盘文档    → 工作日志 / 总计划状态 / 契约或决策（按第六节分层）
⑥ 提交推送    → commit（feat/fix/docs + 一句话）+ push（代理见备忘）
⑦ 汇报       → 按第七节格式，含"下一步"
```

## 六、落盘规则（写哪儿）

| 内容性质 | 落到哪 |
|---------|--------|
| 今天干到哪、下一步 | `工作日志.md`（追加一条） |
| 任务完成/状态变化 | `总计划.md`（勾状态，补实测数字） |
| 项目成果大事记 | `PROGRESS.md`（新增编号项） |
| 接口字段/格式/错误码 | `API_CONTRACT.md`（走 v1.x 流程）+ 同步冻结版策略 |
| 为什么这么定（选型、权衡） | `决策记录.md`（ADR 格式） |
| 分工、流程、协作规则 | `接口.md` |
| 阶段性成果/交付说明 | 单独文档（如 `端到端流程设计.md`） |

**判定法**：如果一条信息“三个月后还有人会问”，就必须落盘。

## 七、汇报格式（AI 每次交付固定用）

```
【已完成】一句话结论 + 实测数据（PASS/FAIL 数字，不给"应该没问题"）
【改动文件】列表（新增/修改）
【验收】跑了哪条命令、结果如何、报告路径
【下一步】1~3 条，按优先级
【风险/假设】不确定的地方 + 采用了什么假设
```

## 八、常见反模式（避开）

| 反模式 | 后果 | 正确做法 |
|--------|------|---------|
| 结论只留在对话里 | 下次会话重新讨论 | 5 分钟内落盘 |
| "已完成"但没跑验收 | 联调时集中爆雷 | 无实测数字不叫完成 |
| 顺手重构/美化代码 | 引入无关风险、破坏冻结 | 一次只做一件事 |
| 把假设当结论写进文档 | 后期返工 | 标注"暂定假设" |
| 给李的指令含糊（"优化一下"） | 他只能猜，返工 2 轮 | 写清"改什么文件 + 跑什么命令验收" |
| 用对话里的旧数据当现状 | 判断失准 | 数据以 `runs/` 报告为准 |

## 九、AI 能力边界（用户需知道的）

- **AI 不能替代**：接口决策、与导师沟通、验收签字、对医学语义的最终判断
- **AI 的产出需要验证**：凡涉及"跑通/通过"，以实测输出为准（AI 会展示原始命令输出）
- **AI 的记忆有限**：跨会话只保留已写入持久记忆的项目要点；细节一律靠 `docs/`
- **AI 会犯错**：发现它前后不一致时，以文档和实测为准，直接指出即可纠正

---

## 十、一句话总结

> **AI 负责执行与落盘，人负责决策与验收；所有结论进文档，所有改动过验收，所有边界走授权。**
