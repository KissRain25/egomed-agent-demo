# EgoMed-Agent 部署前检查清单

> 适用：把 EgoMed-Agent 部署到一台**新机器**（演示机 / 验收机 / 课题组另一台电脑）
> 版本口径：软件 v0.2.0，接口契约 v1.0.4
> 用法：从上往下逐项打勾，**任一项不过就不要往下走**。所有命令都在项目根目录执行。

---

## 0. 一张速查表

| 阶段 | 命令 | 通过标准 |
|---|---|---|
| 环境自检 | `egomed.bat doctor` | 返回码 0 |
| 详细检查 | `egomed.bat check` | 十余项全绿 |
| 回归 | `egomed.bat regress` | mock 8/8，real 通过 |

## 1. 硬件（最先查，最容易翻车）

- [ ] **独立显存 ≥ 8 GB**（本项目在 RTX 5060 Laptop 8 GB 上验证）
- [ ] **启动前整卡显存余量 ≥ 5 GB**
      ```powershell
      nvidia-smi --query-gpu=memory.used,memory.total --format=csv,noheader
      ```
      > 实测组成：桌面常驻程序 ~1.0 GB + ASR（Whisper medium）~1.9 GB +
      > YOLO/SAM2 ~1.1~1.8 GB ≈ **启动后即占 4 GB**。
      > 8 GB 卡若不腾环境，跑 20 分钟就会因显存触顶把单帧推理拖到 200 秒级
      > （见 `docs/显存分析与建议.md`）。
- [ ] **演示前关闭占 GPU 的常驻程序**：Wallpaper Engine、浏览器后台标签/WebView、
      NVIDIA Overlay、录屏软件、其他训练/推理进程
- [ ] 内存 ≥ 16 GB（服务端 RSS 实测约 2.6 GB，打包/编码另有开销）
- [ ] 磁盘可用 ≥ 20 GB（权重 0.58 GB + 数据数 GB + 运行产物）

      （最省事：直接跑 `egomed.bat doctor`）
- [ ] 环境路径已写进 `config.toml`（或 `egomed.bat` 能自动定位解释器）

## 6. 部署步骤（按序执行）

```bat
1) 安装环境.bat                  :: 建 egomed 环境（已有环境可跳过）
2) egomed.bat doctor             :: 环境自检，返回码 0 才继续
3) egomed.bat check              :: 详细检查（十余项）
4) egomed.bat warmup             :: 预热 ASR（吃掉冷启动，约 60~100s）
5) egomed.bat regress            :: 回归（mock + real）
6) egomed.bat demo               :: 正式演示：起服务端 → 开现场控制台
```

- [ ] 第 4 步 `warmup` 必须成功（否则第一次语音请求会等 60~100 秒，现场很尴尬）
      > ASR 未就绪时服务端会返回 `503 asr_warming`，客户端按 10 秒节奏自动重试，
      > 上限 300 秒 —— 门控是**兜底**，不是常态。

## 8. 常见故障对照

| 现象 | 错误码 | 下一步 |
|---|---|---|
| 起不来，提示端口被占 | E1002 | 换端口或关掉占用 8000 的程序 |
| 起不来，提示服务端已在跑 | E3003 | 直接复用已在跑的服务端，或先停掉它 |
| 首次语音要等一分多钟 | — | 服务端在加载 Whisper，属于冷启动；跑 `egomed.bat warmup` |
| A2 返回 `503 asr_warming` | — | 正常，客户端会自动重试；若持续超过 300s 说明 ASR 初始化失败 |
| 分割报「画面里没检测到目标」 | — | 对准屏幕、确认选的模态与画面一致 |
| 越跑越慢、单帧几秒到几分钟 | — | **显存触顶**，先腾显存，见第 1 节 |
| 报「YOLO 权重中找不到目标」 | — | 缺对应模态的 `best.pt`，见第 3 节 |

完整错误码表：`软件制作/错误码.md`（每个码都有「一句人话 + 一条下一步」）。


## 10. 已知限制（部署方需知情）

- 智能眼镜**尚未到位**，现阶段以移动终端（手机/平板）替代采集端；接入层（N52）已就绪，
  真机只需填 SDK 桥
- 8 GB 笔记本卡属**下限配置**，必须腾显存才能跑长稳
- 长稳 60 分钟为验收口径，20 分钟内的短测**不足以**判定稳定性
- ASR 使用 medium 模型，首次加载约 55 秒（一次性）

## 11. 服务端加固后的行为变化（2026-11-03，v0.2.1）

> 部署方如果用的是 **0.2.1 之前**的服务端，这一节有 4 条行为差异需要知道。

| 变化 | 现象 | 客户端/部署方要做什么 |
|---|---|---|
| **ASR 预热门控真正生效** | 真引擎刚启动、ASR 推理路径还没热好时，A2 返回 **503 + `state=asr_warming`**（而不是像以前那样卡住 60~180 秒） | 客户端已内置按 `retry_after_s`（10s）重试同一段录音；**自研客户端要照 A.12 实现**，否则第一句话会被丢掉 |
| **ASR 内部故障不再伪装成功** | ASR 真正报错时返回 **HTTP 500 + code 5000**（以前返回 200 + `status:"ok"`，客户端会当成"没听清"） | 按普通故障处理（提示重试），别再当成功 |
| **预热失败会明确报出来** | `/healthz` 返回 **503 + `state=failed`** + `warmup_error`（以前无论成败都报 200，故障推迟到发第一帧才变 500） | 启动自检时若看到 `state=failed`，直接看 `warmup_error`，不要等请求报错 |
| **画面不可用不再返回 400** | 上传空文件/坏画面返回 **200 + `status:"ok"` + 空字段 + `"画面里没检测到目标，请对准屏幕"`**（以前返回 400 + code 2001，违反契约） | 按契约 A1 边界 1 处理：**保留上一帧回显**，不要清屏 |

另有两项**资源治理**（对部署方是好事，不用做什么）：

- 落盘产物会自动裁剪（每个会话的 `seg/` 只留最近 5 张 overlay + 5 张 mask、录音只留 3 段），
  会话超 30 分钟闲置后目录一并删除 —— 不会再出现"跑几场长稳磁盘涨几百 MB"；
  日志 `runs/server_log.txt` 改为滚动写（单文件 10 MB，保留 3 份历史）。
- 上传体积有硬上限（图片/音频各 2 MB），超了返回 1001。正常客户端压缩后远小于此。

还有一处**内容语义变化**（v1.0.6 决议 #16，字段名/类型不变）：

| 变化 | 旧 | 新 |
|---|---|---|
| `candidates`（需要澄清时） | 目标名，如 `["LV cavity", "Left Ventricle"]` | **模态名**，如 `["ACDC (MRI 心脏)", "CAMUS (超声 心脏)"]` |
| 澄清 `message` | 一律说"在多个模态里都存在" | 跨模态歧义才说模态歧义；一次说多个器官时说"识别到多个目标：左肾、肝…（都在 CT 腹部 里）" |

→ 客户端若把 `candidates` 显示给医生看，**现在显示的是模态名而不是内部类名**；
若你的代码拿 `candidates` 去匹配目标名/类名，需要改成匹配模态名（或只用 `message`）。
