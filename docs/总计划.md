## 依赖与顺序

```
N1（独立）──┐
N3（独立）──┼──→ N4 → N5 →（N6 与 N4/N5 并行，李侧）→（N7 视实测）→ N8 → N9 → N10 → N12
            │                                                              ↑
            └── N11 随时按需插入 ────────────────────────────────────────────┘
```

**关键原则**：接口已冻结 v1.0——阶段二/三所有开发**只允许动 client/ 和新增文件**，需动接口的走 v1.x 流程（提出→确认→更新契约→群通知）。

## 子计划（分支）

大任务（预计 >2 小时或含多个里程碑）在开工前先写子计划，本计划只保留一行索引与状态；子计划内自含验收标准、分步实施、风险对策，避免主计划膨胀。

**命名规则**：`docs/子计划_N<编号>_<短名称>.md`

| 子计划 | 父项 | 状态 | 一句话 |
|--------|------|------|--------|
| `子计划_N4_摄像头实时采集.md` | N4 | **v1.2 进行中**（客户端已交付，M1 部分达成；真引擎侧问题见 `联调发现_20260920_真引擎实时链路.md`） | 视频源自动跑通 → 真摄像头实时分割 → 防抖实战 → 语音交互（M1~M5、N4.1~N4.6） |

**子计划模板要素**（写新的照这个来）：① 目标与可量化验收标准 ② 范围（不做什么）③ 架构与文件 ④ 复用清单 ⑤ 分步实施 ⑥ 关键设计决策 ⑦ 风险与对策 ⑧ CLI/接口设计 ⑨ 验收命令 ⑩ 工时估算 ⑪ 待授权事项 ⑫ 完成后联动。
