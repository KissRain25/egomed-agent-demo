# 当众演示说明（N43）

> 一条命令把「系统能跑」和「指标是多少」当场摆出来，并出可留存的报告。
> 脚本：`scripts/demo_day.py`（2026-11-04 新增）

## 一、用法

```powershell
python scripts/demo_day.py                # 全套：预检 -> 起真引擎 -> 验收 -> 延迟 -> 精度 -> N48 演示 -> 面板
python scripts/demo_day.py --quick        # 跳过精度评测（省约 2 分钟）
python scripts/demo_day.py --keep-server  # 跑完不关服务端（现场追问时可直接发帧）
python scripts/demo_day.py --port 8021    # 换端口（默认 8020，避开 8000）
python scripts/demo_day.py --no-panel     # 只跑不打印面板（CI 用）
```

产物：`runs/demo_day/<时间戳>/report.md`（面板文本 + 各子报告路径 + 每步日志清单）。

## 二、它做了什么（**只做编排，不新增能力**）

| 步骤 | 复用什么 | 产出 |
|---|---|---|
| 预检 | GPU 占用 / 权重与分类器 / `data/ACDC` / 端口 | 四项当场报 |
| 起服务端 | `server/api.py --real --port P`（自己起、自己关） | 等 `/healthz` 报 ready |
| ASR 预热 | 先发一条语音 | 吃掉冷启动，避免第一条语音打爆 30s 超时 |
| 验收 | `client/acceptance_test.py --suite real` | 通过数 + 失败项 |
| 延迟 | `client/eval_latency.py --detail` | 每模态均值/P50/P95 + 合并 + 耗时构成前三 |
| 精度 | `client/eval_segmentation.py --mode both` | 在线/离线 Dice + 与基线差值 |
| 新能力 | 未设目标连发 4 帧 | 第几帧起给出模态名 + 提示语 |
| 面板 | 自己拼 | 终端大字表 + report.md |

**为什么复用 CLI 而不是 import 内部函数**：现有回归与评测口径**一个字节没动**，
演示数字与日常评测**必然一致**（不会出现「演示一套、报告另一套」）。

## 四、前置条件（**不满足就会假失败，务必先看**）

1. **GPU 必须空闲**（< 3000 MiB）。外部程序占用会把语音推理从 0.6s 拖到 88~144s，
   表现为「语音用例整片失败」—— **那是环境问题，不是代码问题**。预检会当场报警。
2. **端口空闲**（默认 8020）。预检会报「端口已被占用」——
   若误连到旧服务端，数字会与本次对不上（这是最难查的一类错）。
3. 权重与分类器齐全、**`data/ACDC/img` 存在**（精度评测用；`--quick` 可跳过）。

## 五、失败不崩（现场演示的保护网）

- 每个环节独立执行，挂了**记录原因并继续**；
- 面板末尾给「结论：可当众演示 / 有环节未过（见上方与 report.md）」；
- 每步的原始日志留在 `runs/demo_day/<ts>/*.log`，现场被追问时可当场翻证据。
