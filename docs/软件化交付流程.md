# 软件化交付流程（从"能跑的原型"到"能交付的软件"）

> 创建：2026-10-28 ｜ 维护：闫 ｜ 状态：**v0.1 草案，待确认**
> 配套：`总计划.md`（阶段四/五任务表）、`AI协作规范.md`（改动必绿 / 文档即真相）、`端到端流程设计.md`（架构三层）
> 待确认假设：目标形态为 **Windows 便携包**（解压即用、双击启动），服务端与客户端同机或局域网分离部署均可。若改为"纯网页/服务形式"，第四、五步需重写。

## 一、先定义"软件"在这里指什么

不同人的"软件"是三件不同的事，必须先分清，否则做出来的东西谁都不满意：

| 视角 | 他要的东西 | 现状 |
|---|---|---|
| **演示者**（现场答辩/给导师看） | 双击一个图标 → 选源 → 开始 → 看到画面和指标 | 已有 `启动模拟眼镜.bat` / `现场控制台.bat`，但入口有 11 个 |
| **医生**（未来真机使用者） | 戴上眼镜说话就能看结果，不碰电脑 | 架构已就绪（零智能客户端），缺真机与手机侧转发 App |
| **维护者**（你与李） | 一键回归、出错能定位、能发版 | 组件齐全（回归/长稳/诊断包），缺统一入口与版本号 |

**结论：本轮软件化的目标不是"再造功能"，而是把已有 20+ 个脚本收敛成一个有门面、有配置、有日志、能打包、能发版的软件。** 功能几乎不用新写。

## 二、成熟度阶梯：我们现在在哪一级

| 级别 | 定义 | 判定标准 | 现状 |
|---|---|---|---|
| **L1 能跑** | 单条链路跑通 | 手工命令能出结果 | ✅ 已达成（2026-09-28 真机验证） |
| **L2 一键起** | 无需记命令 | 双击一个入口完成"起服务→起客户端→出结果" | ✅ 基本达成（`启动模拟眼镜.bat`，预热 78s） |
| **L3 连续跑** | 长时间不出事 | 连续 ≥1h 无人工干预不中断、无泄漏 | ◐ 部分（`run_soak.py` 已有，**长稳基线未登记**） |
| **L4 出错能诊** | 故障可自解释 | 任何失败都有明确原因码 + 一键诊断包 | ◐ 部分（`make_diag_pack.py` 有，**无错误码体系**） |
| **L5 能分发** | 别人能装上用 | 解压即用 / 安装包 + 版本号 + 用户手册 | ❌ 未开始（**无本项目打包配置**） |

**本轮要推到 L5。** 关键洞察：L1/L2 已完成，L3/L4 各差一半，L5 为零。

## 三、六个步骤（每步都有完成定义 DoD）

### 步骤 1：入口收敛 —— 11 个 bat 变成 1 个门面

**问题**：根目录现在有 11 个启动器：`启动EgoMedDemo` / `启动复现补跑` / `启动模拟眼镜` / `回归` / `安装环境` / `机位校准` / `查看进度` / `每日回归` / `环境自检` / `现场控制台` + `现场控制台`。用户不知道该点哪个；而且**解释器解析那 6 行候选路径在 11 个文件里完全重复**。

**做法**：
1. 抽出唯一启动器 `egomed.bat`（或 `launcher.py`），只保留一份解释器解析逻辑；
2. 主入口提供子命令，其余 bat 变成转发壳（保留兼容，不破坏现有习惯）：

```
egomed.bat install     → 安装环境
egomed.bat demo        → 一键演示（原 启动模拟眼镜）
egomed.bat console     → 现场控制台（原 现场控制台）
egomed.bat calibrate   → 机位校准
egomed.bat regress     → 一键回归（原 回归）
egomed.bat soak        → 长稳测试
egomed.bat diag        → 生成诊断包
egomed.bat doctor      → 环境自检
```

3. 桌面上只放**两个**快捷方式：「EgoMed 演示」和「EgoMed 维护」。

**DoD**：根目录 bat 数量从 11 → ≤3（主入口 + 安装 + 兼容壳）；解释器解析只有一处；旧 bat 逐个仍能跑通。

---

### 步骤 2：配置集中化 —— 参数不再散在命令行

**现状**：`--fps / --timeout / --renderer / --glasses-queue ...` 全靠命令行记忆，`load_config` 已有雏形但未统一。

**做法**：单一 `config.toml`，三层优先级 **命令行 > 环境变量 > 配置文件 > 内置默认**：

```toml
[server]
url = "http://127.0.0.1:8000"
timeout_s = 3.0

[capture]
source = "video"        # video | cam | url | glasses
fps = 5.0
max_side = 1280
jpeg_quality = 80
max_bytes = 307200

[display]
renderer = "window"     # window | file | glasses-mono | null

[logging]
level = "info"
dir = "runs/logs"
```

**DoD**：删掉命令行参数后仅靠 `config.toml` 仍能完整跑通一次演示；配置错误有明确提示（不是 traceback）。

---

### 步骤 3：可观测 —— 日志规范 + 错误码 + 诊断包

**做法**：
1. **日志统一落盘** `runs/logs/<日期>/egomed.log`，含时间戳/级别/模块/会话 id，单文件超限滚动；
2. **错误码表**（三类，够用即可）：
   - `E1xxx` 客户端（E1001 采集源打不开 / E1002 服务端不可达 / E1003 超时 / E1004 渲染失败）
   - `E2xxx` 服务端业务（沿用契约 `status/message`）
   - `E3xxx` 环境（E3001 解释器缺失 / E3002 依赖缺失 / E3003 端口占用 / E3004 模型权重缺失）
3. **诊断包一键**：`egomed.bat diag` → 日志 + 环境信息 + 最近一次运行报告 + 配置脱敏快照，打成一个 zip。

**DoD**：人为制造 3 种故障（拔网络 / 关服务端 / 占端口），每种都能给出**唯一错误码 + 一句人话解释 + 一条下一步建议**；诊断包能独立说明问题。

---

### 步骤 4：生命周期托管 —— 软件自己管进程

**现状**：`启动模拟眼镜.bat` 已能"起服务端 → 等预热 → 起客户端 → 退出清理"，这是好基础。缺的是：单实例锁、端口占用处理、崩溃自恢复、退出码含义。

**做法**：
1. 启动前检查端口占用，占用则提示"已有实例在跑"并直接附着（而不是报错退出）；
2. 单实例锁文件（`runs/.lock`），避免双击两次起两套服务；
3. 服务端异常退出时客户端给出明确提示（`E1002`）而非卡死；
4. 退出统一清理，不留孤儿进程（`tasklist` 复查）。

**DoD**：连续双击 3 次主入口，不出现端口冲突与僵尸进程；杀掉服务端进程后客户端 5s 内给出明确提示。

---

### 步骤 5：打包分发 —— 别人能装上用

**现实约束（必须先想清）**：
- `setup.py` / `pyproject.toml` **是 SAM-2 上游自带的，不是本项目的打包配置**，不能混用；
- 模型权重体积大（YOLO26m ×5 + SAM2），**不可能打进安装包**；
- 依赖含 torch + CUDA，纯 PyInstaller 打包极易踩动态库坑。

**推荐路线（按风险从低到高）**：
1. **首选：便携运行包**——项目目录 + 固定名 venv（`runtime/`）+ 主入口，解压即用，首次运行自检；权重单独挂载（已有 `runs/yolo26_det/**`，检测目录存在即用，缺失则明确提示 `E3004`）。
2. 备选：PyInstaller `onedir`（不是 onefile），仅打客户端，服务端仍走源码。
3. 不做：onefile 单文件（torch 场景下启动慢且易崩）。

**DoD**：在一台**没装过 conda/egomed 环境**的机器上，解压 → 双击 → 15 分钟内跑出一次分割结果（或明确告诉缺什么、怎么补）。

---

### 步骤 6：验收与发版 —— 让"完成"有证据

**做法**：
1. `egomed.bat regress` 一键跑：mock 8/8 + real 11/11 + ASR/VAD 回归，产出 `runs/reports/<时间戳>/summary.json`；
2. **交付验收清单**（每次发版勾一遍）：一键起 ✓ / 连续 1h ✓ / 故障三例可诊 ✓ / 诊断包可读 ✓ / 演示录制 ✓；
3. **版本号**：软件版本 `v0.x.y`（本项目自有）与**契约版本 v1.0.3 独立演进**，写进 `README` 与诊断包；
4. 打 tag（`v0.1.0`），发布说明只写"变了什么 + 怎么验"。

**DoD**：从干净仓库出发，一条命令产出可交付报告；报告里每个 ✓ 都能指向具体证据文件。

## 五、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 打包踩 torch/CUDA 动态库坑 | 步骤 5 拖延数天 | 优先便携 venv 包，PyInstaller 只做可选实验；先保证 L1–L4 |
| 权重体积大无法分发 | 换机即不可用 | 权重挂载 + 启动自检 + 明确的下载/拷贝指引（`E3004`） |
| 入口收敛破坏现有习惯 | 现场演示点错 | 旧 bat 保留为转发壳，不删除；桌面只留两个快捷方式 |
| 长稳测试暴露显存泄漏 | L3 卡住 | 与服务端 N46 合并；先测后修，测出即登记（不隐藏） |
| 只做门面不做可诊断 | 换个人接手仍无解 | 步骤 3 与 1 并行推进，错误码先落地 |

做完这一步再谈配置化，不要一次摊开六件事。
